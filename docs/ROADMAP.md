## 🚀 Пріоритетний спринт: Offline-first PWA, Черга та Користувачі

### 1. ⚡ UX та Fix офлайн-поведінки (Крок 1)
- **Закриття модалки додавання корови:**
  - При роботі офлайн модалка повинна закриватися **одразу** після запису в локальну чергу IndexedDB (не чекаючи мережевого `fetch`).
- **Виправлення блюру сповіщення:**
  - Тост/повідомлення про додавання в чергу виноситься на верхній шар (`z-index: 9999`), без перекриття backdrop-фільтрами модальних вікон.
- **Приховування вікна логіну для авторизованих користувачів:**
  - Перевірка токена/сесії в `localStorage` до первинного рендеру; модалка логіну не показується і не мерехтить, якщо користувач уже залогінений.

---

### 2. 📦 Список офлайн-черги та керування нею (Крок 2)
- **Інтерфейс черги:**
  - При натисканні на оранжеву кнопку офлайн-статусу або на інформаційний попап відкривається панель/модалка зі списком усіх невідправлених змін.
- **Керування записами (Видалення хрестиком):**
  - Біля кожного елемента черги (нова корова, лікування, осіменіння) додається кнопка **❌ (хрестик)** для скасування/видалення помилково внесеного запису з IndexedDB до синхронізації.
  - Кнопка *"Спробувати синхронізувати зараз"* для примусової відправки при появі мережі.

---

### 3. 💾 Повне фонове кешування бази ферми (~900 КБ) (Крок 3)
- **Офлайн-картки корів:**
  - Вся база тварин ферми (~900 КБ) фоново підвантажується в IndexedDB після входу або вибору активної ферми.
  - Пошук, фільтрація та перегляд карток корів працюють 100% автономно без інтернету (актуально для роботи безпосередньо в корівнику).
- **Оцінка RAM & Навантаження:**
  - Розпарсений JSON обсягом 1 МБ у V8 займає всього **~2.5–3.5 МБ RAM** (для порівняння: вкладка браузера бере 30–50 МБ).
  - Дані лежать на диску в IndexedDB і не навантажують пам'ять смартфона чи планшета.
- **Розподіл версій (Free vs Pro):**
  - **Базова версія:** Повний офлайн-перегляд і черга для активної поточної ферми.
  - **PRO-версія:** Багатофермовий кеш, офлайн-аналітика/звіти, автоматична фонова фокус-синхронізація (Background Sync API).

### 4. 👥 Керування користувачами та правами (Крок 4)
- **Прив'язка до ферм:**
  - Можливість призначати користувачу доступ лише до визначених ферм.
  - Редагування імені, контактів та ролі користувача з UI панелі.
- **Дефолтна роль:**
  - За замовчуванням новий користувач створюється як `farm_admin` (адміністратор однієї своєї ферми).

### 5. 🗜️ Оптимізація та зменшення розміру UI (Крок 5)
- **Поточний розмір:** `index.html` ~250 КБ (4 167 рядків). Потенціал зменшення — **на 60–70% (до ~60–80 КБ)**.
- **Дії для оптимізації:**
  - **SVG-спрайти:** Винесення десятків інлайн-SVG у єдиний спрайт `<svg><use href="#id"/></svg>` (економія ~40–50 КБ).
  - **Уніфікація модалок через Petite-Vue:** Заміна дубльованої розмітки форм ветеринарних подій динамічними шаблонами `v-if` / `v-for`.
  - **Мережева компресія:** Brotli/Gzip на Cloudflare Pages автоматично стискає залишковий обсяг до ~35–45 КБ при передачі клієнту.
  - **Перемикач метрик на кнопках та плитках (`%` vs `Голови`):**
    - Додати компактний перемикач режиму відображення в шапці або налаштуваннях:
      - `[ Голови ]` — для практичної щоденної роботи ветлікаря та доярки (абсолютна кількість корів на бейджах).
      - `[ % ]` — для директора/зоотехніка під час аналізу структури стада без роздування бейджів великими числами.
      - Стан перемикача зберігається локально в `localStorage`.

---

### 6. 🖨️ Чистий мобільний друк завдань (Clean B&W Print Table / 0 байт)
- **Контекст використання на фермі:**
  - На телефоні CSV-файли практично не потрібні (ветлікарі та доярки не працюють з таблицями Excel на смартфонах).
  - Потрібен простий паперовий або PDF чек-лист для дошки в корівнику або планшета ветлікаря.
- **Вимоги до друкованої сторінки (`@media print`):**
  - **Абсолютно біла сторінка (Zero Design Glitz):** Жодних кольорових плашок, темних фонів, заокруглень кутів (`border-radius: 0`), тіней (`box-shadow: none`) чи градієнтів.
  - **Прямі чорно-білі лінії:** Класичні тонкі чорні рамки таблиці (`border: 1px solid #000`), що легко читаються при будь-якому освітленні й не витрачають тонер/картридж.
  - **Чітка структура чек-листа:**
    - Заголовок: Назва ферми, дата формування списку та назва завдання (напр., *«Список на перевірку тільності»* чи *«Каренція молока (Антибіотики)»*).
    - Колонки: **№ Корови | Офіційний номер | Секція/Група | Подія / Діагноз | Термін каренції | Квадрат для галочки [  ] / Підпис**.
  - **Приховування UI:** Повне зникнення меню навігації, кнопок, модалок та статус-барів.
  - На iOS/Android викликається через `window.print()` в один дотик: миттєвий друк на Wi-Fi/Bluetooth принтер або збереження в ідеально чистий PDF.

### 7. ⚡ Оптимізація D1 Quota та багатокористувацький ETag-кеш
- **Контекст лімітів:** Денний ліміт Cloudflare D1 (5 000 000 рядків/день) оновлюється щодня, чого вистачає для роботи кількох користувачів із запасом у 10 разів.
- **Мультикористувацька синхронізація через ETag/Version:**
  - У таблиці `farms` зберігається колонка `version` / `updated_at`.
  - Будь-яка зміна тварини Користувачем А інкрементує версію ферми.
  - Користувач Б надсилає заголовок `If-None-Match: "v42"`. Якщо нічого не змінилося — повертається швидкий `304 Not Modified` без повторного читання рядків стада. Якщо версія нова — Користувач Б миттєво отримує свіжі дані без конфліктів.
